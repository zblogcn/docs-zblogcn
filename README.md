# Z-Blog 官方文档

本仓库为 Z-BlogPHP 与 Z-BlogASP 的官方文档源码，基于 VitePress 构建，文档内容存放于 `src/` 目录（`src/php/`、`src/asp/`），站点配置位于 `.vitepress/config.mts`。

## 贡献方式

欢迎参与 Z-Blog 文档的编写，贡献方式如下：

1. Fork 本仓库
2. 在 `src` 目录下编写文档
3. 提交 Pull Request

## 文档写作原则

以读者能理解并完成任务为目标，优先保证事实准确、操作清楚、文字与界面一致。文档也应便于搜索与引用，但不为关键词密度、固定字数或统一模板牺牲可读性。

修改旧文档时，应结合当前程序界面、实际配置和验证结果判断。原稿、截图和旧文档之间有冲突时，先核对；无法确认的版本限制、功能行为和操作结果，不要补写成确定事实。

### 内容与结构

- 每篇正文使用一个 `#` 标题，随后用一至三句话交代主题、使用场景和读者能完成的事情。不要在标题后直接堆放截图。
- 正文使用 `##` 和 `###` 组织内容，确有必要时使用 `####`。章节长度以能讲清楚为准，不设最低字数。
- 功能概览说明入口、主要信息和后续操作；操作教程按实际操作顺序说明前提、步骤和如何确认结果；故障排查说明现象、原因判断和处理方法。不要求每篇套用同一结构。
- 版本要求、权限和依赖条件会影响操作时，在对应步骤前说明，并核实适用范围，例如标注"1.7.0 版本起"。
- 操作说明尽量写清"在哪里、点击什么、接下来看到什么"。有多条处理路径时，说明如何选择。
- 首次提到容易陌生的缩略语时简要解释，例如"CSRF（跨站请求伪造）"。无需为读者熟悉的术语另设词汇表。
- 常见问题和相关文档按需添加。只有实际问题或有帮助的后续入口时才增加，不为凑结构编造问答。

### Frontmatter

文档开头可使用 VitePress 支持的写法示例：

```yaml
---
title: 下载安装
description: 介绍 Z-BlogPHP 的下载渠道、环境要求与安装步骤，帮助用户完成首次部署。
---
```

| 字段            | 使用要求                                                                                        |
| ------------- | ------------------------------------------------------------------------------------------- |
| `title`       | 推荐显式填写，并与正文 H1 保持一致；标题应准确、简洁                                                                |
| `description` | 推荐填写，用一至两句概括主题与适用场景，自然包含程序名称（Z-BlogPHP / Z-BlogASP）；会输出为页面的 meta description，供搜索引擎与 AI 工具引用 |

**注：**

1. `description` 不使用几个字的标签，也不为固定字数填充内容；
2. `keywords`、`tags` 等字段 VitePress 原生不会输出到页面，如需生效须在 `.vitepress/config.mts` 中另行配置；
3. frontmatter 仅辅助检索与引用，正文的准确性、完整性与可验证性同样重要，不为凑关键词牺牲正文质量。

### 图片与代码

配图存放在 `src/public/img/` 的对应目录下，Markdown 中使用以 `/img/` 开头的站内路径：

```markdown
![后台网站设置页面](/img/php/start-option/website-settings.png)
```

- 图片必须有说明含义的非空 alt 文本，不使用本机绝对路径或 Windows 盘符路径。
- 截图应清晰展示与步骤相关的区域；发布前检查账号、凭据和其他不应公开的信息。
- 每张图应能对应附近的操作或说明。连续截图展示不同步骤时，补上必要文字，不让读者仅靠图片猜测流程。
- 截图中的示例域名、路径等不能默认当作读者环境中的实际值。
- 命令、参数、文件名和路径使用行内代码；代码块标注语言，例如 `css`、`php`、`html`、`js`。

### 链接与排版

站内页面引用优先使用相对 Markdown 文件路径或站点路由，例如：

```markdown
[下载安装](/php/start-install)
[模板标签](/php/dev-theme#模板标签)
```

跨栏目或使用站点路由时，按实际配置核对地址；外部链接使用有意义的链接文字。内容分片目录（`php/app-*/`）下的文件通过 `@include` 嵌入正式页面，不生成独立路由，不要直接链接到这些文件。

使用站点默认字体和颜色。段落之间留一个空行，标题、列表和代码块与相邻内容之间也留空行。表格用于便于比较的字段或选项，不为了排版而嵌套 HTML 表格。

界面名称与截图保持一致，使用「中文直角引号」标识，例如「后台管理」「模块管理」。正文中的中文与英文、数字之间适当留空格；引用界面原文时保留界面写法。

使用简洁、准确的书面语，删除无助于理解的重复说明和宣传性表述。术语拼写按程序的正式名称，例如 `Z-BlogPHP`、`zb_users`、`c_option.php`，不把旧词表中的偏好当成绝对规则。

### 复用内容与文法约定

- 需要重复使用的内容（如路径说明、术语解释）单独写进 `src/php/terms/` 等目录下的片段文件，在目标文档中用 `@include` 语法引用，避免多处维护。
- 文法约定（路径用行内代码、名词概念用「」、整段强调用「**注：**」「**重要：**」等）详见「[文档规范](/php/guide-docs)」。

## 提交前检查

先检查本次修改的内容：

- 页面归属、标题与侧边栏配置（`.vitepress/config.mts`）是否正确。
- 操作入口、按钮名称、截图和预期结果是否对应。
- 条件和限制是否有依据，代码及占位符是否清楚。
- 图片是否可用，链接是否指向正确页面，`@include` 引用路径是否存在。
- 本地预览中标题、列表、图片和提示块是否正常。

随后运行：

```bash
git diff --check
pnpm run docs:build
```

构建失败时，根据报错处理链接、包含文件或模板语法等问题。构建成功仅代表源码能够生成站点，不能代替程序功能验证，也不代表已经发布上线。

### AI 文档导出

按 llms.txt 提案组织 AI 文档：主索引提供背景和导航，分类索引供按需检索，单篇 Markdown 对应实际网页地址。每次 `pnpm run docs:build` 时自动生成以下 AI 友好文件，无需手工维护：

| 输出 | 用途 |
| --- | --- |
| `dist/llms.txt` | 文档目录索引，包含站点介绍、分类导航及每篇文档的标题和链接 |
| `dist/llms-full.txt` | 全文聚合文件，汇总所有 Markdown 文档的完整内容，供 AI 工具一次性读取 |
| `dist/**/*.md` | 单篇 Markdown，与在线页面一一对应，附带网页原文链接 |
